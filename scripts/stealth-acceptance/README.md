# Stealth audit acceptance

This rig is for issue 729's combined review branch. Its workflow runs only on the contributor fork, on disposable GitHub-hosted machines. The script refuses local and self-hosted execution. No personal Chrome profile, browser cookies or account credentials are supplied.

The headed job uses Chrome for Testing on Xvfb, a fresh profile and separate CLI/native-host directories for each mode. Chrome's internal sandbox remains enabled. The workflow permits user namespaces in the disposable Ubuntu VM so Chrome can create that sandbox. The tested binary and browser download are hashed in the evidence.

The fixture matrix checks native double-click event order and application effect, covered/moved targets, minimal contenteditable input, annotation coordinates and page mutations across scroll/device scale/frames, coordinate-hover globals, and background-tab focus through the real unpacked extension. Same-origin frame input is verified and unmappable cross-origin input must refuse before dispatch. Relay fault injection observes live hover listeners in their actual isolated world before rejecting input, and verifies required-isolation failure without an implicit main-world retry. CLI calls and fixture serving are asynchronous. Results and screenshots are retained as workflow artifacts even on failure.

The optional `editors_only` dispatch installs pinned Lexical, ProseMirror and Monaco packages on the hosted runner using pnpm with dependency install scripts disabled. The lockfile generated by the first hosted install is committed; subsequent runs use frozen resolution and retain the lockfile/dependency versions as evidence. Assets are bundled for a local fixture server and checks read authoritative editor models. Monaco deliberately uses its supported textarea input option with an inaccessible module API to exercise the clipboard fallback. Default EditContext mode is outside that fixture's claim. Only the disposable fixture profile receives clipboard permissions; no real clipboard data is used.

This is acceptance work in progress. Real package results, broader interruption behavior, additional transformed/nested frame cases, and public detectors remain separate requirements. The manual Windows control jobs compare an observed process-custody timeout against the audited base; they do not assume the timeout's cause.

The optional `benchmark_only` dispatch builds the audited base and combined source, then runs the existing public detector script on the same hosted VM, with independent profiles and native-host directories. Per-command outputs, exit codes, binary hashes and source revisions are retained. A failed detector is not automatically attributed to the patch: compare baseline and combined results, including load failures. GitHub's public IP, a virtual display, fresh profiles and the relay test driver's browser debugging port limit how closely this represents a signed-in user's environment. These results cannot guarantee detector evasion or account safety.

The original full CI manual run exercises the existing headless E2E suite separately. The optional `annotation_only` dispatch runs the permanent screenshot E2E regression after geometry changes; `monaco_e2e_only` runs the permanent native paste/copy and clipboard restoration regression. Those legacy helpers often disable Chrome's internal sandbox, making the disposable runner the isolation boundary for those separate runs.
